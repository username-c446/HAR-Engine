## Сквозные ограничения

### Индекс аватара мира ≠ сетевой peer-id (важно для тех, кто читает код)

В этом движке две разные «оси» идентификации игрока, и их **нельзя смешивать**:

- **Индекс аватара мира** — позиция в `AvatarManager::mAvatarArray`. Количество
  аватаров задаёт `GameplayManager::GetNumPlayers()`, а миссия
  фиксирует его в **1** (`missionmanager.cpp:174`, `SetNumPlayers(1)`). Поэтому
  `GetAvatarForPlayer(0)` — это **единственный аватар процесса, локальный
  игрок этой машины**, на любом клиенте. Это НЕ «хост» в сетевом смысле.
  (Исключение — локальный сплитскрин `supersprintmanager.cpp:2614`, где
  `GetNumPlayers()>1`; там индекс 0 = первый локальный P1.)
- **Сетевой peer-id** — `net::Session::GetLocalPeerId()` (поле `m_selfId`),
  выдаётся сервером по порядку подключения: `ServerEndpoint` присваивает
  `id = m_nextPeerId++` (ServerEndpoint.cpp:67). Хост-процесс коннектится
  сам на себя первым (loopback в `StartHost`), поэтому получает **id 0**;
  присоединившиеся клиенты — **1, 2, 3…**. Этот id служит только для
  маршрутизации и фильтрации собственного эха — он не является индексом
  в `AvatarManager`.

**Почему это важно:** совпадение «индекс аватара 0 == сетевой id 0» у хоста —
артефакт порядка подключений, а не семантика. На клиенте сетевой self-id = 1,
а локальный аватар мира всё равно индекс 0. Не тащите сетевой id в вызовы
`GetAvatarForPlayer(id)` и не считайте, что `GetAvatarForPlayer(0)` означает
«первый из многих»: при `SetNumPlayers(1)` это просто «локальный».

**Баг, который это стерегло:** `GamePlayerBridge` изначально держал
`m_selfId = 0` по умолчанию и логировал «эхо» через `from == m_selfId`
(GamePlayerBridge.cpp:43). На клиенте от этого отбрасывалось состояние ХОСТА
(чей peer-id ровно 0), и хост вообще не отображался удалённо. Исправлено:
`NetworkMatchManager::Update()` каждый кадр синхронизирует bridge с настоящим
self-id сессии (`m_bridge->SetLocalPeerId(GetLocalClientId())`). Не удаляйте эту
синхронизацию — фильтрация эха bridge станет неверной.

- **Почти все NPC/трафик-системы захардкожены под `GetAvatarForPlayer(0)`**
  (~140 мест): педы, трафик, AI-акторы реагируют только на игрока 0. Нужно:
  обходить все аватары (каркас добавлен — `AvatarManager::GetNumAvatars()` и
  `FindNearestAvatar()`; паника педов уже циклит по всем) либо рассылать
  host-авторитетный результат.
- **Сильная зависимость от `rand()`** (цвет машины, импульс удара, выбор
  педа-водителя): чистый детерминированный повтор ненадёжен → предпочтителен
  host-авторитетный расчёт + рассылка событий через `net::`.
- **Глобальных игровых часов нет**: статика мира сидится `worldSeed`
  (`Game::GetRandomSeed()`); динамика остаётся локальной по дизайну
  (docs/WORLD_SYNC_PLAN.ru.md §3-5). Переменный dt (game.cpp:483) исключает
  полный lockstep.
